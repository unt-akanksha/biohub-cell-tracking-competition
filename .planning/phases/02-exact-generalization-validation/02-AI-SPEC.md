## 1. System Classification

**System Type:** Deterministic scientific-ML evaluation and promotion system

**Description:**
The system evaluates 3D+time cell-tracking graphs produced by learned models. It lets one competition researcher decide whether a candidate improves clean biological tracking on complete, held-out embryo movies. Good output is bitwise-reproducible from pinned scorer code, immutable manifests, prediction graphs, and a declared policy; it separates detection, ordinary-link, and division behavior and never infers quality from leaderboard score alone.

**Critical Failure Modes:**
1. Scorer drift, coordinate drift, or aggregation drift reports a false improvement.
2. Training/calibration and evaluation share embryo source material.
3. A metric exploit, incomplete graph, or missing movie is accepted as a candidate.
4. Pooled gains conceal a severe embryo, movie, node-recall, or division regression.
5. A promotion cannot be reproduced from source, manifest, and artifact hashes.

## 1b. Domain Context

**Industry Vertical:** Developmental-biology microscopy and scientific machine learning

**User Population:** A competition researcher training and selecting zebrafish cell-tracking models

**Stakes Level:** High for competition validity and scientific integrity; not a clinical system

**Output Consequence:** Promoted candidates consume scarce GPU hours and submission slots and may become final competition entries.

### What Domain Experts Evaluate Against

| Dimension | Good | Bad | Stakes | Source |
|---|---|---|---|---|
| Node localization | Timepoint-aware optimal matches lie within 7 µm in physical coordinates | Voxel/axis confusion or duplicate matches | Edge endpoints become invalid | Organizer metric specification |
| Ordinary links | Both matched endpoints reproduce a GT edge with few evaluable wrong alternatives | Greedy or proxy accuracy misses graph-level FP/FN behavior | Dominant score term degrades | Organizer metric specification |
| Cell divisions | Two distinct directed daughter branches satisfy the local ±1-frame window | Fake forks, shared/merged branches, fork reuse | Invalid biological topology and exploit risk | Patched organizer division metric |
| Sparse labels | Unannotated predictions are treated according to organizer rules while node-count excess is penalized | Unmatched nodes are naively scored as false positives or entirely ignored | Biased detection calibration | Organizer metric specification |
| Generalization | Both reciprocal embryo holdouts and complete movies improve or remain within declared tolerance | Random clips share source material or one embryo collapses | Private-test failure | Competition data provenance |

### Known Failure Modes in This Domain

- Random edge/movie splits leak embryo-specific morphology, motion, illumination, and repeated source material.
- Proxy parent top-1, training loss, or per-movie mean can move opposite to the micro-aggregated exact score.
- `(z,y,x)` voxel distances are wrong unless converted using the official physical scale; time must never be treated as a spatial coordinate.
- Sparse annotations make ordinary precision/recall assumptions invalid, while excess total nodes still trigger the adjusted-Jaccard penalty.
- Divisions are extremely rare; a small number of fabricated or malformed forks can dominate the weighted division term.
- Missing output movies and CSV/GEFF conversion drift can invalidate otherwise strong predictions.

### Regulatory / Compliance Context

No clinical regulation applies. Competition rules, public-access/licensing requirements, reproducibility requirements for winning solutions, metric-integrity policy, and the prohibition on hand-labeling test/validation data are binding.

### Domain Expert Roles for Evaluation

| Role | Responsibility |
|---|---|
| Competition researcher | Defines baseline/candidate pairing, approves explicit trade-offs, and audits provenance |
| Scorer maintainer | Pins organizer code and validates adversarial regression fixtures |
| Cell-tracking practitioner | Reviews biological topology diagnostics and unusual worst-movie failures |

## 2. Framework Decision

**Selected Framework:** Pinned `royerlab/tracking_cellmot` organizer implementation with NumPy/SciPy/Polars/GEFF adapters and pytest

**Version:** Exact upstream Git commit SHA recorded in `config/official-baseline.lock.json`

**Rationale:**
The target is a deterministic scientific metric, not an LLM or agent workflow. Reusing the organizer implementation maximizes leaderboard fidelity; a narrow local adapter adds provenance, manifests, decomposition, round trips, and policy without forking metric semantics. Pytest supplies fast regression gates and the Phase 1 JSONL ledger supplies offline traceability.

**Alternatives Considered:**

| Framework | Ruled Out Because |
|---|---|
| Independent pure-Python metric rewrite | Useful only as a cross-check; it can silently diverge from patched organizer topology semantics |
| `traccuracy`-only evaluation | General tracking metrics do not reproduce the competition-specific sparse-label penalty and division window |
| Hosted experiment/eval platform | Kaggle inference is Internet-disabled and evidence must remain reproducible offline |
| Arize Phoenix | LLM/trace observability adds dependencies without improving deterministic graph-score fidelity; existing JSONL evidence is the chosen override |

**Vendor Lock-In Accepted:** Partial — organizer scorer semantics are intentionally authoritative, but inputs/outputs use open GEFF/CSV/JSON formats and all source hashes are recorded.

### Key Abstractions

| Concept | What It Is | When You Use It |
|---|---|---|
| Scorer lock | Upstream commit, file hashes, license, constants, and adapter version | Every exact evaluation |
| Frozen manifest | Canonical movie/source memberships and hashes | Training, calibration, and evaluation |
| Exact report | Counts, scores, diagnostics, bootstrap deltas, and provenance | Candidate comparison and ledger completion |
| Promotion decision | Deterministic policy result plus hashed evidence | Advancing, reviewing, or rejecting a candidate |

### Common Pitfalls

1. Averaging per-movie Jaccards instead of the official weighted/micro aggregation.
2. Passing voxel coordinates where micrometre coordinates or `(t,z,y,x)` ordering is expected.
3. Treating absence of annotated ground truth as an ordinary false positive.
4. Evaluating only round-tripped CSV without proving direct GEFF parity.
5. Updating the official dependency without regenerating lock hashes and scorer fixtures.

## 4. Implementation Guidance

**Model Configuration:** Evaluation is model-agnostic. A report always records model/config hashes, seeds, split manifest SHA-256, candidate/baseline artifact hashes, and scorer lock SHA-256.

**Core Pattern:** Validate provenance and complete coverage, evaluate baseline and candidate through the same pinned adapter, retain raw sufficient statistics, derive deterministic decompositions and paired deltas, then apply a versioned policy.

**Tool Use:** Git/GitHub retrieve organizer source; GEFF/tracksdata load graphs; NumPy/SciPy implement diagnostics/bootstrap; Polars or stdlib CSV validates tables; pytest freezes regressions. Kaggle CLI is read-only in this phase.

**State Management:** Immutable JSON reports and manifests are content-addressed. Ledger decisions append hashes and never rewrite prior evidence.

**Context Window Strategy:** N/A — no generative model is invoked. Large graph data is streamed movie-by-movie; only compact sufficient statistics are retained in memory.

## 4b. AI Systems Best Practices

### Structured Outputs with Pydantic

```python
from decimal import Decimal
from pydantic import BaseModel, ConfigDict

class ExactMetric(BaseModel):
    model_config = ConfigDict(extra="forbid", frozen=True)
    adjusted_edge_jaccard: Decimal
    edge_jaccard: Decimal
    division_jaccard: Decimal
    score: Decimal
    edge_tp: int
    edge_fp: int
    edge_fn: int
    division_tp: int
    division_fp: int
    division_fn: int
```

Invalid, non-finite, negative-count, or extra-field payloads fail before ledger persistence. The implementation may use the existing standard-library validator if adding Pydantic would harm Kaggle portability, but its contract must be equivalent and regression-tested.

### Async-First Design

Not applicable: exact evaluation is local CPU-bound work over movie graphs. Deterministic sequential evaluation is preferred; optional process-level parallelism must sort results before aggregation and prove byte-identical output.

### Prompt Engineering Discipline

N/A — no prompt or LLM judge participates in model selection.

### Context Window Management

N/A — stream complete movies and avoid retaining volume arrays when graph statistics suffice.

### Cost and Latency Budget

Phase 2 consumes zero GPU hours. The full regression suite should finish in under 30 seconds on synthetic fixtures; a complete real OOF report should record CPU time and peak memory.

## 5. Evaluation Strategy

### Dimensions

| Dimension | Rubric | Measurement Approach | Priority |
|---|---|---|---|
| Organizer fidelity | Adapter matches pinned organizer results and constants on every fixture | Code | Critical |
| Exploit rejection | All former fake-fork/sentinel/merged-branch cases score or fail exactly as patched semantics require | Code | Critical |
| Leakage safety | Manifest train/eval source sets are disjoint and identities complete | Code | Critical |
| Round-trip fidelity | Direct GEFF and CSV↔GEFF reports are identical within declared exact tolerance | Code | Critical |
| Coverage | Every expected complete movie appears exactly once with finite valid graphs | Code | Critical |
| Generalization | Pooled and bilateral embryo deltas meet the versioned policy | Code | High |
| Tail behavior | Worst-movie, density, displacement, node, and division diagnostics remain inside policy | Code plus targeted human review | High |
| Reproducibility | Re-run with identical hashes produces canonical byte-identical report | Code | Critical |

### Eval Tooling

**Primary Tool:** Pytest plus the pinned organizer scorer; Phase 1 JSONL/Markdown tracker replaces hosted tracing.

**Setup:**

```bash
python -m pip install -e .
python -m pytest -q tests/test_scorer.py tests/test_manifests.py tests/test_evaluation.py tests/test_promotion.py
```

**CI/CD Integration:**

```bash
python -m pytest -q && python -m compileall -q src tests
```

### Reference Dataset

**Size:** At least 12 synthetic/adversarial graph fixtures plus all available complete held-out movies for real reports.

**Composition:** Perfect graphs, missing/extra nodes, wrong endpoints, coordinate-boundary matches, excess-node penalty, no-event movies, early/on-time/late divisions, fake forks, branch merge/reuse, invalid times, aggregation imbalance, missing coverage, and round-trip samples.

**Labeling:** Synthetic expected counts are derived from the pinned organizer specification and cross-run through the organizer scorer. Real labels are official competition GEFF annotations only; no hand labeling.

## 6. Guardrails

### Online (Real-Time)

| Guardrail | Trigger | Intervention |
|---|---|---|
| Scorer provenance | Lock/source hash mismatch | Block evaluation |
| Manifest leakage | Overlapping or unknown source identity | Block evaluation |
| Graph integrity | Invalid time, non-finite coordinate, duplicate ID, malformed fork | Block candidate |
| Complete coverage | Missing or extra movie | Block candidate |
| Metric-hack policy | Known exploit signature or prohibited topology intent | Reject candidate |
| Promotion evidence | Missing baseline pairing or required diagnostic | Return `review_required`/reject; never promote |

### Offline (Flywheel)

| Metric | Sampling Strategy | Action on Degradation |
|---|---|---|
| Scorer regression parity | Every commit touching scoring/I/O | Block merge and inspect upstream drift |
| Bilateral embryo delta | Every completed candidate | Retire, recalibrate, or document trade-off |
| Worst-movie delta | Every complete report | Inspect density/motion/coverage strata |
| Division counts | Every candidate with forks | Review local topology cases |

## 7. Production Monitoring

**Tracing Tool:** Existing append-only JSONL experiment ledger and content-addressed exact reports; Arize Phoenix explicitly rejected as unnecessary/offline-incompatible for this deterministic non-LLM system.

**Key Metrics to Track:** scorer-lock hash, manifest hash, complete movie count, pooled/bilateral/worst-movie deltas, node recall/count penalty, edge/division TP/FP/FN, CPU runtime, and peak memory.

**Alert Thresholds:** Any provenance/coverage/integrity failure blocks immediately. Promotion thresholds are loaded from the versioned policy; no silent fallback values exist.

**Smart Sampling Strategy:** Always inspect the worst movie, largest density/displacement strata regressions, any division regression, and any baseline/candidate disagreement within 0.25 µm of the node-match threshold.
