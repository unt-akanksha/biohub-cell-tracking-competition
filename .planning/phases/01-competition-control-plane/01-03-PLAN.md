<objective>
As a Biohub competitor, I want Kaggle launches to fail closed before they threaten quota or fail late so that the 8-hour reserve and every expensive experiment remain protected.

Deliver machine-enforced authorization, preflight evidence, a reusable notebook watchdog contract, and a launch wrapper. Phase 1 verifies the wrapper with fakes and live read-only quota/status only; it must not push a kernel.
</objective>

<threat_model>
ASVS level 1; block at high severity. Threats are quota parse failure interpreted as zero risk, time-of-check/time-of-use races, forged or stale preflight evidence, command injection into kernel paths/refs, authorization replay for a different experiment, watchdog failure to persist terminal status, and accidental real launch during tests. Mitigations: Decimal fail-closed arithmetic, quota/status recheck at authorization and launch, content-hash binding plus short expiry, strict path/ref validation, experiment/run binding, atomic heartbeat/checkpoint manifests, injected launch runner, and an explicit `--execute` plus confirmation token unavailable in fixture tests.
</threat_model>

<must_haves>
  <truths>
    <truth>SAFE-01: Authorization requires parseable live GPU quota, no active/conflicting GPU kernel, a registered experiment, and a declared runtime greater than zero.</truth>
    <truth>SAFE-02: `projected_remaining = remaining - declared_max_runtime`; exactly 8.00 hours is allowed and any value below 8.00 is rejected using decimal arithmetic.</truth>
    <truth>SAFE-03: The notebook watchdog begins shutdown before the declared deadline, calls registered checkpoint/flush callbacks, and writes one terminal status even when a callback fails.</truth>
    <truth>SAFE-04: Every launch binds evidence for imports, inputs, one batch, applicable forward/backward, checkpoint round trip, and output location.</truth>
    <truth>SAFE-05: A runtime strictly greater than 1.00 hour additionally requires dense-memory and complete dataset-coverage preflights.</truth>
    <truth>Authorization expires, is single-use, and is bound to experiment ID, kernel ref/path, quota snapshot hash, runtime, reserve, and preflight hashes.</truth>
    <truth>The launch wrapper rechecks live quota and active kernel status immediately before push; changed state can invalidate an earlier authorization.</truth>
  </truths>
  <prohibitions>
    <prohibition statement="Never authorize or launch when quota/status parsing is unavailable, ambiguous, stale, or malformed" status="unverified" verification="backstop" />
    <prohibition statement="Never reduce or bypass the 8-hour reserve through rounding, runtime omission, or a local override flag" status="unverified" verification="backstop" />
    <prohibition statement="Never run Kaggle kernel push in the Phase 1 test suite or setup verification" status="unverified" verification="backstop" />
    <prohibition statement="Never accept preflight success without content-hashed evidence bound to the registered experiment" status="unverified" verification="backstop" />
  </prohibitions>
</must_haves>
