<objective>
As a Biohub competitor, I want every experiment and decision recorded as immutable lineage so that score gains, failures, and GPU cost remain comparable across sessions.

Extend the Phase 1 tracer with a real append-only event store, lifecycle CLI, deterministic progress projection, and seed records for the expensive prior experiments already audited.
</objective>

<threat_model>
ASVS level 1; block at high severity. Threats are ledger corruption from interruption or concurrent writers, silent mutation of historical evidence, malicious or accidental path references outside the workspace, forged artifact hashes, and terminal/Markdown injection from free-form descriptions. Mitigations: exclusive lock, one JSON object per line, flush plus fsync before lock release, strict schema/state transitions, append-only amendments, workspace-root path resolution, hash verification, bounded text fields, and Markdown escaping in projections.
</threat_model>

<must_haves>
  <truths>
    <truth>TRACK-01: Registration creates a stable unique run ID and immutable event containing hypothesis, parent, configuration, code/data/model hashes, seeds, split, and declared maximum runtime.</truth>
    <truth>TRACK-02: Terminal events append actual runtime, quota delta, artifact/report hashes, status, failure reason, exact pooled/embryo/fold metrics, and worst-movie delta when supplied.</truth>
    <truth>TRACK-03: Original event bytes never change; corrections are new amendment events referencing an existing event ID.</truth>
    <truth>TRACK-04: Progress reconstructs lineage and displays status, evidence, GPU-hour cost, promotion decision, and highest-priority next gate.</truth>
    <truth>Registering the same explicit run ID twice fails; generated IDs combine UTC time, normalized slug, and collision-resistant suffix.</truth>
    <truth>One writer owns the ledger lock; interrupted/truncated final lines are quarantined and reported before new events append.</truth>
    <truth>Legal transitions are registered to started to one terminal status, followed by zero or more decision/amendment events; illegal transitions fail without writing.</truth>
  </truths>
  <prohibitions>
    <prohibition statement="Never rewrite, reorder, compact, or delete historical experiment events" status="unverified" verification="backstop" />
    <prohibition statement="Never mark an experiment promoted solely from public leaderboard score" status="unverified" verification="backstop" />
    <prohibition statement="Never accept a claimed artifact hash without hashing an existing workspace-approved file when a path is supplied" status="unverified" verification="backstop" />
    <prohibition statement="Never hide failed, rejected, incomplete, or superseded runs from the default progress history" status="unverified" verification="backstop" />
  </prohibitions>
</must_haves>
